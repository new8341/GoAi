## 类别

- **R 运行层可信度**（user, debug）：整次调研是否具备可辩护的工程与科学前提
- **P 文献语料**（user, debug）：召回文献是否贴题、可外部核对
- **G Gap 科学质量**（user, debug）：缺口主张是否像真科学问题
- **E 证据真实性**（user, debug）：quote 是否原文、provenance 是否可回源
- **T 类型名实相符**（user, debug）：contradiction / missing_link 等是否名副其实
- **A 可行动与可证伪**（user, debug）：下一步与证伪是否可设计实验/计算
- **N 新颖性诚实与过宣称**（user, debug）：是否把常识/已知当发现
- **X 交叉一致**（debug, user）：报告、面板、JSON、audit 是否一致
- **D 领域物理 sanity**（user, debug）：材料/热电专家主观判断（无自动 ground truth）

## 等级

- `must`：必须通过才可答辩
- `should`：应当通过；失败需书面理由
- `expert`：领域专家主观（无自动 ground truth）

## 判决选项

`pass` / `fail` / `unsure` / `na`

## 标准明细

| ID | 等级 | 标题 | 适用对象 | 核对问题 | 通过标准 | 失败信号 |
|----|------|------|----------|----------|----------|----------|
| R1 | must | 生产验收 PASS | run | production_verification.status 是否为 PASS？ | status=PASS；关键 checks 全为 pass | FAIL；或仅有 demo checklist 冒充生产 |
| R2 | must | 一致性检查 | run | consistency.ok 是否为 true？ | ok=true 或 issues 为空 | paper_id 悬空、证据跨文错挂 |
| R3 | should | AI 科学门禁 | run | science_review.status 是否 PASS（若已跑）？ | science_review=PASS；或明确标注未跑 | L0 hard fail / L1 reject>0 仍宣称科学通过 |
| R4 | should | 贴题监控 | run | optimization_metrics 贴题/对齐是否达标？ | topic_hit_rate≥0.7 且 gap_material_alignment≥0.8 | 大量 Bi2Te3/GeTe 等非主题材料冲榜 |
| R5 | must | 全文证据比例 | run | 含全文文献是否达到可辩护比例？ | fulltext_papers/papers ≥ 配置阈值（常见≥50%） | 几乎全是摘要冒充全文证据 |
| P1 | must | 标题贴题 | paper | 该文献标题/摘要是否明确涉及主题材料（如 SnSe）？ | 标题或摘要出现主题材料名 | 仅广义 thermoelectric，主材料是 Bi2Te3/GeTe/SnS 等 |
| P2 | should | 性质相关 | paper | 是否涉及 vacancy / lattice thermal conductivity / phonon 等主题性质？ | 至少命中一个主题性质词或其同义表述 | 只谈合成产率、器件封装等无关主线 |
| P3 | must | 可外部核对 | paper | 是否有 DOI 或稳定 URL 可人工打开核对？ | 有 DOI 或 oa/pdf URL | 只有内部 id，无法外链 |
| P4 | should | 解析来源可信 | paper | fulltext_source 是否为 mineru / grobid / grobid_fusion（非 local_cache）？ | parser-derived fulltext 或明确无全文 | local_cache 被当作生产证据 |
| G1 | must | 真缺口而非常识复述 | gap | Gap 标题/描述是否提出可争论的未决问题，而非教科书常识？ | 存在不确定性、冲突、覆盖缺口或方法缺口 | 「SnSe 是热电材料」类陈述 |
| G2 | must | 主张与主题对齐 | gap | 该 Gap 是否服务于当前 topic（材料+性质）？ | 标题/描述点名主题材料，或明确为语料级 limitations/missing-link | temporal-PbTe 等偏离主材料 |
| G3 | should | 粒度足够细 | gap | 是否具体到机制/条件/度量，而非空泛「需要更多研究」？ | 含可操作对象（缺陷类型、温度区间、对比协议等） | 只有模板句、无物理量/机制 |
| G4 | should | 与 Known 区关系诚实 | gap | 若 overlaps_known，是否仍合理保留为「语料内缺口」而非全球新发现？ | 表述限定在 screened corpus / candidate missing_link | 宣称首次发现已知密集区 |
| E1 | must | quote 像论文原句 | evidence | 摘录是否像论文措辞（而非模型改写口号）？ | 句法/术语像学术正文 | 宣传腔、明显 LLM paraphrase |
| E2 | must | quote⊂原文 | evidence | 在对应 chunk/全文中能否搜到连续原句（允许空白差异）？ | 关键词串可定位；机器 hint 为 hit 时仍需肉眼确认截断是否误导 | 搜不到；或只有参考文献/许可协议噪声 |
| E3 | must | provenance 齐全 | evidence | 是否具备 paper_id + chunk_id + pdf_hash（或等价定位）？ | 三者齐全且 paper_id 在文献列表中 | 缺 provenance；paper_id 不存在 |
| E4 | must | 非 boilerplate | evidence | 摘录是否避开 CC 许可、Peer review、Data availability、纯参考文献块？ | 正文/结果/讨论类内容 | Creative Commons / Reprints / References 堆砌 |
| E5 | should | 主张–摘录相关 | evidence | 该 quote 是否实质支持 Gap 主张（而非无关公式/题头）？ | 摘录语义指向 gap 标题所涉问题 | κ 公式、作者单位、与主张无关段落 |
| T1 | must | contradiction 双边 | gap | 若类型为 contradiction：是否有不相交的 supporting 与 contradicting 文献集？ | 两边非空且 paper_id 集合不相交 | 单边凑 contradiction；两边同一篇 |
| T2 | should | contradiction 真有冲突 | gap | 两边文献在归一化条件后是否真的主张冲突（而非时代叙述差）？ | 可写出冲突点（度量/机制/结论）对照表 | 仅「都讨论了 SnSe」 |
| T3 | should | missing_link 限定语料 | gap | missing_link 是否明确是「本语料内未覆盖」而非「全世界没有」？ | 描述含 corpus / screened / within this corpus 等限定 | 绝对化「文献从未研究」 |
| T4 | should | underexplored 有开放问题 | gap | underexplored 是否指向 limitation/uncertainty，而非已完成结论？ | 证据含 however/remain/challenge 等开放信号，或明确未决机制 | 摘录全是成功结论句 |
| A1 | must | 下一步可执行 | gap | suggested_next_step 是否能在一周内设计成具体实验/计算/数据库检查？ | 含对象、手段、判据之一 | need more research / further study |
| A2 | must | 证伪可设计 | gap | falsification_test 是否给出「何种结果则关闭/拒绝该 Gap」？ | 条件→拒绝/关闭 的清晰逻辑 | 空泛「如果错了就算了」 |
| A3 | should | 与 Route A/外验可衔接 | gap | 若启用 Route A：下一步是否能落到 MP/OQMD/可计算量？ | 可映射到结构/稳定性/物性查询或计算 | 完全无法外验的纯修辞缺口 |
| N1 | must | 无过宣称 | gap | 是否避免「首次发现/证实发现/paradigm shift」等过强措辞？ | 措辞克制，标明候选/语料内 | discover / 首次证明 / paradigm |
| N2 | should | novelty 与 known 一致 | gap | novelty 分数是否与 overlaps_known / 领域常识一致？ | known 重叠时 novelty 不应虚高（>0.7 需警惕） | 明显已知仍标高 novelty |
| X1 | must | 面板与 JSON 一致 | run | 用户端展示的 Gap 数/标题是否与 gaps.json 一致？ | 条数与 id 对齐 | 缓存 user_result 陈旧导致不一致 |
| X2 | should | 报告不矛盾 | run | report.md 中 Gap 列表是否与 gaps.json 主张一致？ | 无另一套互相矛盾的叙事 | 报告写 PASS 叙事但 JSON 证据为空 |
| X3 | should | 检索后端如实 | run | 若宣称 Sciverse：audit 是否无意外 OpenAlex fallback？ | source/audit 与宣传一致 | 宣传 Sciverse 实为 fallback |
| D1 | expert | 物理机制合理性 | gap | 以热电/缺陷物理常识看，该 Gap 是否值得跟进？ | 专家主观：值得 / 低优先 / 不值得（记录理由） | 机制明显违背已知约束且无新证据 |
| D2 | expert | 实验可行性 | gap | suggested_next_step 在真实实验室/计算资源下是否可行？ | 专家评估周期、设备、样品可行性 | 需不可得极端条件却当作常规下一步 |
| D3 | expert | 文献代表性质疑 | gap | 当前 10 篇语料是否足以支撑该 Gap，还是抽样偏差？ | 专家注明：语料足够 / 需补检关键综述或关键实验文 | 关键里程碑文献缺失仍强推 contradiction |

## 核对对象如何生成

对每次运行调用 `build_expert_review_pack`：
- 运行层：verification / consistency / science_review / metrics / 全文率 / 交叉一致
- 每篇文献：P1–P4
- 每个 Gap：G/T/A/N/D 等
- 每条证据：E1–E5（含 quote、chunk_preview、provenance）

当前 `production` 示例共生成 **156** 条核对项。
