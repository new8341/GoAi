# Materials Agent 使用说明

面向日常运行与答辩演示的操作手册。  
项目功能 / 架构 / 创新 / 风险总览见 [`README.md`](README.md)；**赛题完成度与优化方向**见 [`完成度与优化方向.md`](完成度与优化方向.md)；赛题与冲分策略见 [`readme_agent.md`](readme_agent.md)；依赖见 [`DEPENDENCIES.md`](DEPENDENCIES.md)。

> 文档分工（对齐竞赛工作区习惯）：  
> - `README.md` = 评委与协作者读的「是什么、怎么构成、风险在哪」  
> - `完成度与优化方向.md` = 「要求完成了哪些、做了什么、方法是什么、还差什么」

## 1. 环境准备

### 1.1 进入项目目录

```bash
cd tracks/algorithm/materials_agent
```

Windows PowerShell 同样适用。

### 1.2 安装 Python 依赖

```bash
pip install -r requirements.txt
# 可选：Cursor SDK 后端
pip install ".[cursor-sdk]"
```

### 1.3 配置 `.env`

```bash
copy .env.example .env   # Windows
# cp .env.example .env   # macOS / Linux
```

至少填写：

| 变量 | 用途 | 是否必须 |
|------|------|----------|
| `OPENALEX_EMAIL` | OpenAlex 礼貌联系邮箱 | 生产建议必填 |
| `OPENALEX_API_KEY` | OpenAlex 免费 API Key（[申请](https://openalex.org/settings/api)） | 生产强烈建议 |
| `UNPAYWALL_EMAIL` | Unpaywall 查询邮箱 | 生产建议必填 |
| `S2_API_KEY` | Semantic Scholar API Key（[申请](https://www.semanticscholar.org/product/api)） | 可选；第二检索后端 |
| `SCIVERSE_API_TOKEN` | 赛题推荐文献库 Sciverse | 可选；有 Token 后可用 `configs/production_sciverse.yaml` |
| `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `OPENAI_MODEL` | 可复现 LLM | 要用 LLM 时必填，且账户需有余额 |
| `MP_API_KEY` | Materials Project 外验 | Route A 真库验证时必填 |
| `CURSOR_API_KEY` | 可选 Cursor 后端 | 可选；Windows 本地桥可能失败并自动 fallback |
| `GROBID_BASE_URL` / `QDRANT_URL` | 本地服务 | 默认 `http://localhost:8070` / `6333` |

文献库申请路径见 [`docs/文献库获取与缺口.md`](docs/文献库获取与缺口.md)；  
**免费权威论文库 + 逐库注册用法**见 [`docs/免费权威论文库与注册指南.md`](docs/免费权威论文库与注册指南.md)。  
本轮 Sciverse 结果人工核验步骤见 [`docs/人工核验_production_sciverse.md`](docs/人工核验_production_sciverse.md)。

**不要**把 `.env`、密钥或受限 PDF 提交到 Git。

### 1.4 复赛最短复现（评委路径）

完整步骤见仓库外 [`submissions/semi_final/REPRODUCE.md`](../../submissions/semi_final/REPRODUCE.md)。摘要：

```powershell
docker compose up -d grobid qdrant
# 金标 LLM-off
powershell -File scripts/reproduce_production_sciverse.ps1
py -3 scripts/export_survey_latex.py outputs/production_sciverse
# 同 seed 消融
py -3 scripts/ablate_route_a.py --bundle-dir outputs/production_sciverse --seed 42
py -3 scripts/serve_viewer.py
```

Profile 三分法：`demo_local` / `production_sciverse`（LLM-off）/ Route A（可 LLM）— **禁止混说**。

### 1.5 生产环境额外组件

```bash
docker compose up -d grobid qdrant
```

当前 **`configs/production.yaml` 默认 GROBID 主解析**（`secondary: none`）。请先确认：

- GROBID：`http://localhost:8070/api/isalive` → `true`
- Qdrant：`http://localhost:6333`

可选 MinerU（`default` / 部分 Route A 配置仍可能启用；Windows 上易被残留进程挂死）：

```powershell
$env:MINERU_MODEL_SOURCE='local'
$env:HF_HUB_DISABLE_SYMLINKS='1'
# 确认 mineru 在 PATH；本地模型见 DEPENDENCIES.md
```

## 2. 三种运行配置（先选对 profile）

| 配置 | 命令 | 适用场景 |
|------|------|----------|
| 离线演示 | `-c configs/demo_local.yaml` | 代码冒烟、无外网 |
| 默认在线 | `-c configs/default.yaml` | OpenAlex 元数据/摘要开发 |
| 生产证据链 | `-c configs/production.yaml` | OA PDF → 解析 → 可验证 Gap |
| Semantic Scholar | `-c configs/production_semantic_scholar.yaml` | S2 检索；失败回退 OpenAlex |

**重要**：`demo_local` 的 checklist PASS **不等于** 生产已验证。生产表述必须以 `verify_production.py` 为准。

## 3. 常用命令

### 3.1 离线演示

```bash
python scripts/run_survey.py survey -c configs/demo_local.yaml
python scripts/verify_checklist.py
```

产物目录：`outputs/demo/`

### 3.2 生产全文证据链

```bash
python scripts/run_survey.py survey -c configs/production.yaml
python scripts/verify_production.py -c configs/production.yaml
```

产物目录：`outputs/production/`  
成功时 `production_verification.json` 中 `"status": "PASS"`。

检索到的文献会额外归档到：

```text
data/<搜索主题>_<YYYYMMDD_HHMMSS>/
  ├── manifest.json    # 主题、时间、Query、统计
  ├── papers.json      # 文献元数据与是否下到 PDF
  ├── README.md
  ├── pdfs/            # 合法 OA PDF（能下到的）
  └── abstracts/       # 摘要文本（每篇一篇 .txt）
```

关闭归档：在配置里设 `retrieval.archive_literature: false`。

### 3.3 Route A（结构–性能假说 + MP 外验）

基于已有 survey 产物（推荐，不必重跑全文解析）：

```bash
python scripts/run_route_a.py -c configs/production_route_a.yaml --bundle-dir outputs/production --out outputs/production_route_a
```

或在 survey 时一并开启：

```bash
python scripts/run_survey.py survey -c configs/production.yaml --route-a
```

产物：`route_a_spr_candidates.json`、`route_a_external_validation.json`、`route_a_spr_report.md`

### 3.4 质量与稳定度

```bash
python scripts/check_quality.py
python scripts/score_against_gold.py
python scripts/run_stability.py -c configs/demo_local.yaml --seeds 41,42,43
pytest tests -q
```

### 3.5 Gap 科学抽检（科学意义）

**默认跑 AI 门禁**（L0 机械 + L1 双角色，无需真人）：

```bash
py -3 scripts/science_review_gate.py -c configs/production.yaml --run outputs/production
```

标准与阈值见 [`experiments/reviews/科学抽检标准_AI可执行.md`](experiments/reviews/科学抽检标准_AI可执行.md)。  
可选真人加分仍按 [`experiments/reviews/README.md`](experiments/reviews/README.md)。

## 4. 两套 Web 界面（请区分）

同一命令启动两种界面：

```bash
python scripts/serve_viewer.py
```

| 界面 | 地址 | 给谁用 | 能做什么 |
|------|------|--------|----------|
| **用户界面（黑盒）** | http://127.0.0.1:8765/ | 验收 / 黑盒测试 / 演示 | 输入主题 → 选模式 → 查看 Gaps / 文献 / 报告 |
| **调试界面** | http://127.0.0.1:8765/debug/?run=production | 开发者 | 检查 verify、全文来源、provenance、Route A 细节 |

### 4.1 用户界面（黑盒测试）

1. 打开 http://127.0.0.1:8765/
2. 输入研究主题（可先从「备选主题」下拉选一项自动填充，也可自填/改写）
3. 选择模式：
   - **快速演示**：本地样例（`demo_local`），适合冒烟与黑盒流程测试
   - **在线检索**：OpenAlex（需网络）
   - **生产全文**：OA PDF + **GROBID**（默认）；可选 MinerU（需服务，耗时长）
4. 可选勾选 Route A
5. 点击「开始调研」，等待完成后查看结果页

用户结果**不展示** audit、pdf_hash、parser 错误等内部字段（便于按黑盒标准评测）。

### 4.2 调试界面

打开 http://127.0.0.1:8765/debug/?run=production ，可切换 `outputs/` 下历史产物，查看验收项与证据 provenance。

### 4.3 注意

- 同时只允许一个调研任务运行。
- 不要直接双击 HTML 文件；必须通过 `serve_viewer.py` 访问。
- 生产模式前请确认 **GROBID / Qdrant** 已就绪（见 §1.4）；仅在启用 MinerU 的 profile 下再检查 MinerU。
- **用户端与调试端：同源不同步**。两侧读同一 `outputs/<run>`；用「调试端/用户端打开本 run」或 URL `/?run=` · `/debug/?run=` 对齐。页签与专家判决不实时同步。对齐条展示 verify / science / 贴题等门禁，便于定优化方向。

## 6. 常见问题

### Q1：`verify_production` 失败，`parsed=x/10` 不够？

- 确认 GROBID 可用；若配置启用 MinerU，再设 `MINERU_MODEL_SOURCE=local`。
- 生产配置已设 `allow_text_cache: false`，不要用 demo 的 `.txt` 冒充全文。
- 付费墙 PDF（403）不会绕过；仅尝试 Unpaywall / Europe PMC / OSTI / arXiv 等合法 OA 直链。

### Q2：界面能开，但 LLM 相关结果像“没增强”？

- 检查 OpenAI 是否有余额（`credit_balance_exhausted`）。
- Windows 上 Cursor 本地桥可能报 `WinError 10038`；已配置时会尝试 OpenAI fallback。
- `audit.json` / Route A 的 `llm_score_unavailable` 表示调用未成功，属诚实降级。

### Q3：Materials Project 报错？

- 确认 `MP_API_KEY` 有效，且 `allow_offline_fallback: false` 时不会静默用 offline stub。
- 可删除 `data/materials_db_cache.json` 后重试。

### Q4：可视化端口被占用？

```bash
python scripts/serve_viewer.py --port 8766
```

## 7. 推荐最小演示流程（约 10–30 分钟，视环境而定）

1. `docker compose up -d grobid qdrant`（若尚未启动）
2. 已有 `outputs/production/` 可跳过重跑；否则执行 §3.2
3. `python scripts/serve_viewer.py`
4. 浏览器打开 **用户界面** http://127.0.0.1:8765/ ，用「快速演示」跑一遍黑盒流程
5. （可选）打开 **调试界面** `/debug/?run=production` 核对内部证据
6. （可选）`python scripts/run_route_a.py ...` 后在调试页切换到 `production_route_a`
