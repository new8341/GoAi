## 3.1 规则路径 vs LLM 路径 / Materials Project 外验（半页对照）

> 对应手册进阶路线「方法创新 30% · 可信与验证 30%」。证据：`outputs/production_route_a/`（`route_a_run_summary.json`、`route_a_external_validation.json`、`route_a_spr_report.md`）。

**同一搜索环、两条角色轨迹（可并存于同一次跑次）：**

| 维度 | 规则路径（可复现基线） | LLM 路径（深度融合） |
|------|------------------------|----------------------|
| 入口 | `seed_template` 按 Gap/材料–性质模板播种 | `llm_seed_refine` 将种子改写成可证伪单句假说 |
| 评分 | 启发式 plausibility / gap_alignment | `llm_score` 输出 `{plausibility, mechanism, keep}` |
| 剪枝与变异 | `rule_mutate` / `mutate` | `llm_prune_soft`、`llm_focus_mutate` 引导邻域搜索 |
| 失败留痕 | 不伪装成功 | 可出现 `llm_score_unavailable`（额度/限流）；**不覆盖已成功的 LLM 角色记录** |
| 本跑次 `roles_seen` | `seed_template`, `rule_mutate`, `mutate`, … | `llm_seed_refine`, `llm_score`, `llm_prune_soft`, `llm_focus_mutate`（另见 unavailable 尾迹） |

**外部验证（与是否走 LLM 解耦，统一打脸）：**

| 项 | 结果 |
|----|------|
| 提供者 | Materials Project（真 API，非 offline 冒充） |
| Top-K 外验 | **pass × 5**（`external_verdicts` 全 pass） |
| 角色标记 | 通过者追加 `external_pass` |
| 含义 | 假说须落到可查询 motif；稳定/能量等库内信号用于软调分，**防止「只会写句子」刷新颖性** |

**读法（给评委）：** 规则路径保证无密钥也可复现搜索骨架；LLM 路径证明 SEED→SCORE→PRUNE→MUTATE 已接入模型；MP 外验证明候选不止文本自洽。三者写在同一 `role_trace` 链上，可分别关断做消融，不互相冒充。
